# benchmark 结果 CSV 约定

结构参照 `kvlang/benchmark/`：脚本产出 CSV，人只读 CSV，不手填任何数字。

## 文件命名

```
result/csv/results-<suite>-<版本>-<UTC 时间戳>.csv
```

- `suite`：`malloc` 或 `kvspace`；
- 版本：对应仓的 commit 短哈希（如 `83ddabb`），**不带仓名前缀**；
- 时间戳：`YYYYMMDDTHHMMSSZ`，脚本生成，不用手写。

示例：`results-malloc-83ddabb-20261113T120000Z.csv`、`results-kvspace-83ddabb-20261113T120000Z.csv`

## 公共列（两类 suite 都必须有）

```
suite,implementation,workload,metric,value,unit,version,timestamp,notes
```

- `suite`：`malloc` / `kvspace`；
- `implementation`：被测或对照实现（`slotsbox`、`glibc`、`jemalloc`、`kvspace`、`lmdb`…）；
- `workload`：负载名（如 `alloc-only/size=64`、`ycsb-a`）；
- `metric`：`p50`、`p99`、`ops_per_second`、`rss_bytes`、`reserved_bytes`、`fragmentation_ratio`、`recovery_ok`…；
- `value` / `unit`：数值与单位（`ns`、`ops/s`、`bytes`、`ratio`、`bool`）；
- `version`：实现的版本或 commit；
- `timestamp`：UTC；
- `notes`：缺失依赖、跳过原因、配置差异等，必须写实。

## malloc suite 附加列

```
allocator,size_class,pattern,threads,operation
```

`pattern` ∈ `alloc-only | lifo | fifo | random | churn`；`operation` ∈ `alloc | free | realloc`。

## kvspace suite 附加列

```
value_size,key_depth,threads,percentile
```

`percentile` 只对延迟指标有效；吞吐填 `-`。

## 硬规则

1. CSV 只由脚本写；评审前不手改数值；
2. 缺失的对照库在 `notes` 写 `skipped: <库> not installed`，不许伪造行；
3. 每份 CSV 头部由脚本写入 `# generated by <script> at <timestamp> version=<v>` 注释行（或单独 `meta.json`），保证可追溯。
